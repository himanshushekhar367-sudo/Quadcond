Condition-aware prediction of G-quadruplex and i-motif propensity, with what each head may claim written into the software.

QuadCond demonstrates reproducible condition effects on measured stability while keeping genomic proxies, derived labels and direct biophysical evidence scientifically separate. It is not yet a validated general folding predictor for either structure.

No public instance yet. A hosted deployment at IIT Delhi is pending. Until then the service runs locally: one process serves both the HTTP API and the AENNA-3D browser workbench on a single port, and quadcond assets fetch verifies every model file by SHA-256 before installing it.

The result the project rests on

The model separates potassium from sodium on sequences it has never seen

An R² of 0.670 would look the same whether a head reads which cation is present or only how much monovalent salt there is. So the atlas was searched for sequences measured both K⁺-only and Na⁺-only at comparable concentration and pH.

StatisticMeasuredOut-of-foldIn-sample
mean ΔTm(K−Na)+12.9 °C+13.6 °C [12.0, 18.4]+13.5 °C [11.0, 21.6]

The held-out interval on sign agreement excludes chance: the head gets the direction right, at close to the right magnitude, on a sequence it has never been shown. Memorisation is visible and quantified rather than hidden — it buys +0.223 of Pearson r and 1.5% of sign agreement. An earlier release reported the in-sample column alone, which was a mechanistic consistency check described as verification.

What this does not license

Accuracy on an individual construct cannot be read off that aggregate. Eight of the 151 sequences carry published values that disagree with each other by more than 10 °C at the same nominal buffer; hTelo 22AG alone spans −4.7 to +32.1 °C across its matched pairs. Nor is the titration curve physically shaped: a K⁺ ladder from 0 to 200 mM gives a 32–45 °C span with four non-monotonic steps out of 32 on a four-construct panel. Read endpoints, not slopes.

Install and run

One process, one port

quadcond serve serves the API and the built workbench together, so a deployment is one process and one URL.

1 Install the package

Python 3.11 or newer. The pinned scientific stack (scikit-learn 1.8.0, xgboost 3.2.0) is what the released model files were built with; loading them under other versions is allowed but reported in every run's provenance block.

git clone https://github.com/himanshushekhar367-sudo/Quadcond.git
cd Quadcond
python -m pip install -e .
2 Fetch the verified assets

Model and atlas files are not in git — they are binary artefacts of a training run, checked by SHA-256 against quadcond/assets_manifest.json. Nothing is downloaded implicitly and no asset is installed unverified.

quadcond assets status   # where each asset is expected, and whether it verifies
quadcond assets fetch    # download and verify the recorded assets
quadcond assets path     # resolved model and atlas paths
3 Build the workbench and serve

The startup banner says whether it found a built workbench, so you know before opening a browser whether / will be the application or the health document. With no build present the service is API-only.

npm --prefix web install
npm --prefix web run build      # writes web/dist
quadcond serve --port 8765      # then open http://localhost:8765/

--host 0.0.0.0 accepts connections from other machines. There are no accounts and no sessions, so do that only on a network you trust.

4 Check it came up ready

/health and /ready are deliberately different questions. A process whose required model file is missing is alive but not ready, and a load balancer should be able to tell.

curl -s localhost:8765/ready | python -m json.tool
python -m pytest tests -q       # runs without the model binaries

The three parts

quadcond/

Python package: twelve calibrated prediction heads, a sequence and conditions feature stack, a motif atlas, a CLI and an HTTP service.

web/

AENNA-3D — a React, TypeScript and Three.js workbench that talks to that service and renders refusals rather than numbers where a head declines.

bridge/

Helpers for pulling AlphaGenome variant scores and joining them to a QuadCond mutation scan on an exact coordinate match.

Claim registry

Twelve heads, and what each is allowed to claim

They are not twelve versions of the same thing, and the difference is not accuracy — it is what was measured. Every prediction carries three fields that say so.

has_experimental_observation — was anything measured upstream of this label? · target_semantics — biophysical, genomic_proxy, derived or predicted · biophysically_grounded — is the label a physical measurement of the structure this head predicts? Only the third licenses a folding or stability claim.

Behaviour

What the software refuses to do

Refusal is a first-class result here, not an error path. A head asked about a sequence outside the region its training data covers returns a refusal with a reason, and the frontend renders that refusal rather than a number.

  • A refused head cannot be read as a score. Downstream code reads the result through a discriminated union, so treating a refusal as a number is a compile error rather than a silent zero.
  • Out-of-allowlist condition heads omit their keys. value, interval and folded_fraction_at_condition are absent, so a consumer that forgets to check the flag gets a KeyError. A flag next to a number relies on every downstream reader remembering which one wins.
  • Folding heads refuse genomic windows. They are oligonucleotide models and do not transfer, so they refuse windows longer than their training range and point at genome-scan, which is a different model trained on G4-seq. A benchmark loss forced that split.
  • Every run carries provenance. The model file's SHA-256, a three-valued matches_manifest (true / false / unknown — never a bare false when the manifest simply has no entry), the build environment, and whether the current environment matches it.
  • competition reports each strand on its own. No combined "which structure wins" score: the two motifs sit on opposite strands of the same duplex, and no combination rule in this package is calibrated against data that would support one.
  • Withdrawn. A Boltzmann ensemble over G4, i-motif and unfolded was served in v0.4.2 and has been removed: the state competing with both at physiological conditions is the duplex, and it was not in the partition function — nor was strand concentration or stoichiometry. The joint 2×2 table, the signed preference_g4_minus_im and the sentence naming a favoured structure are gone too. They were labelled experimental, and the label did not change what they claimed.
  • Mixed evidence tiers are refused, not averaged. A synthetic artifact leads with "SYNTHETIC MODEL — not for scientific use" and the service refuses it unless explicitly started for it. Mixed tiers poison rather than dilute a claim, because nobody can say which rows drove which prediction.

What is still missing is the experiment: one duplex, both strands, a condition grid, and a measurement of which structure wins at each point. Until that exists, no head here can say which fold a locus adopts in a defined buffer — only which antibodies bound it in one cell line.

Command line

Working from a shell

quadcond info                                   # version, assets, heads, claim basis
quadcond predict GGGTTAGGGTTAGGGTTAGGG --k 100
quadcond scan --fasta window.fa --heads g4_tm,im_pht
quadcond competition <sequence>                 # both strands, scored separately
quadcond sweep <sequence> --vary k --start 0 --stop 150
quadcond atlas summary
quadcond genome-scan --fasta promoters.fa --out regions.csv
quadcond report --out report.html

The sequence above is the 21-nt human telomeric G-rich repeat, and --k 100 sets 100 mM K⁺. genome-scan is deliberately a different model from predict: it finds genomic windows first, then their motifs.

Variant effects

Joining a mutation scan to AlphaGenome

quadcond variant matches a QuadCond mutation scan to AlphaGenome variant scores for the same edits, exactly on (chromosome, position, ref, alt) — never by proximity.

# No key needed: the published AVI Tabix bundle
quadcond variant --fasta hg38.fa --chromosome chr22 --start 10510000 --end 10510200 \
    --avi-tabix /data/alphagenome/avi.tsv.gz

# Cheap pre-check: motif screening only — no model, no query, no key
quadcond variant --fasta hg38.fa --chromosome chr22 --start 10510000 --end 10510200 --screen

Four sources sit behind one contract — Tabix bundle, table export, live API and a null source — and the resolver prefers the Tabix bundle because it is the permissively licensed one. --screen exists because most windows have no canonical motif at all: it checks the reference and every single-base alternate on both strands and returns one of motif_present, motif_gain_possible, borderline or no_motif, so a query is only spent where a structural delta is possible.

The worked example is a negative one

examples/chr22-negative-control/ is a complete run: 183 variants, all 183 paired to a regulatory score, and zero structural deltas — the window carries no canonical motif on either strand, at G4Hunter 0.262. It is kept precisely because it is negative. It shows the join, the provenance block and the refusal path working on a window where the honest answer is "nothing to report", which is the common case.

A substitution that destroys the motif carries no delta, and since v0.5.1 it is nonetheless placed structurally high in the 2×2 by category, as structural.basis = "motif_lost", rather than left unclassified: it is the strongest structural result the scan can produce, and it had been sinking to the bottom of a table ranked on absolute delta.

Comparison

Against twelve published tools

On grouped hold-outs and, where a tool's training recipe is public, with that tool retrained on the same folds.

G4Hunter, pqsfinder, QGRS Mapper, G4Catchall, G4Boost, DeepG4, G4detector, G4mismatch, G4ShapePredictor, G4STAB, iM-Seeker and G4SNVHunter.

Where it wins

Buffer-resolved melting temperature, buffer response, measured single-substitution ΔTm, and i-motif transitional pH. These are the questions the condition stack was built for, and no compared tool takes a buffer as input.

Where it lost

Genomic G4 detection — badly enough to change the software. The folding heads now refuse genomic windows and point at genome-scan, a separate G4-seq-trained model. The benchmark that forced the split is recorded in docs/GENOME_SCAN.md.

Grouping is by sequence-similarity cluster rather than at random throughout, because a random split over an atlas where one construct contributes hundreds of measurements reports memorisation as generalisation.
