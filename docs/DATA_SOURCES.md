# Data sources

Every record carries **two** independent provenance axes. Training code opts into both
explicitly; nothing is mixed silently.

**Evidence tier** — where the number came from:

| tier | meaning |
|---|---|
| `experimental` | somebody measured this |
| `derived` | QuadCond constructed it from something else (shuffles, complementary strands) |
| `predicted` | another model's output |

**Label class** — what the label actually measures. This is a different question, and
conflating the two is how genomic occupancy data ends up training a folding model:

| class | meaning | may train |
|---|---|---|
| `biophysical` | a structural property measured in a defined buffer (CD, UV melting, NMR, X-ray) | folding and stability heads |
| `genomic_proxy` | antibody or sequencing occupancy in cells (BG4 ChIP, iMab CUT&Tag) | its own heads, evaluated separately — never pooled with biophysical labels |
| `catalog` | a motif call or candidate listing | nothing on its own, in either direction |
| `synthetic` | generated by a formula | software tests only |

A BG4 ChIP peak and a UV melting curve are both `experimental`. They are not the same
kind of evidence, and the atlas refuses to pretend otherwise. Filter with
`quadcond atlas ...` or, in training, `TaskSpec(label_classes=("biophysical",))`.

*(The label-class axis and its policy wording are adapted from the source
registry of an earlier prototype implementation.)*

## Bundled and reachable

### 1. G4ShapePredictor topology dataset — `experimental`

- **What**: 1,005 G4-forming DNA sequences with experimentally assigned folding topology
  (parallel 487 / hybrid 302 / antiparallel 216), each traced to a PDB entry, a
  literature citation, or in-house CD by the G4SP authors.
- **Source**: `g4sp supplementary/G4 Dataset.xlsx`, <https://github.com/donn-liew/G4ShapePredictor>
- **Cite**: Liew D., Lim Z.W. & Yong E.H. (2024) *Machine learning-based prediction of DNA
  G-quadruplex folding topology with G4ShapePredictor.* Sci Rep 14:24238.
  doi:[10.1038/s41598-024-74826-2](https://doi.org/10.1038/s41598-024-74826-2)
- **Condition caveat**: the table does **not** report per-sequence salt, pH or temperature.
  QuadCond writes the K⁺ reference buffer and flags *every* condition field as imputed,
  plus `condition_not_reported` / `k_buffer_assumed` QC flags. This is why `g4_topology`
  refuses to claim cation sensitivity.
- **Redundancy**: greedy 4-mer clustering at cosine ≥ 0.90 collapses the 1,005 sequences
  into 617 groups, with one cluster of 126 near-identical sequences. Random-split CV on
  this dataset overstates performance; QuadCond uses grouped folds throughout.

### 2. G4STAB web database — `predicted`

- **What**: ~1.9 M rows — human genomic PQS scored by the G4STAB deep ensemble under five
  ionic conditions (100 K⁺; 50 K⁺; 100 Na⁺; 50 K⁺/50 Na⁺; 70 K⁺/30 Na⁺), with gene
  annotation, phastCons and phyloP, and a per-row standard error.
- **Source**: `data/pred_seqs_*.csv`, <https://github.com/donn-liew/g4stab-web-database>
- **Cite**: Liew D., Dharmatilleke A.D., See E. & Yong E.H. (2025) *G4STAB.* Bioinformatics
  41(10):btaf545. doi:[10.1093/bioinformatics/btaf545](https://doi.org/10.1093/bioinformatics/btaf545)
- **These are model outputs, not measurements.** They may be used as a benchmark, as a
  condition-response prior, and for genomic context. The `g4_tm_distilled` head is trained
  on them and is labelled as a distillation everywhere it appears.

### 3. Composition-matched negatives — `derived`

Altschul–Erikson dinucleotide-preserving shuffles of the experimental positives, generated
in-house. Preserve exact mono- and dinucleotide counts; destroy the four-tract register.
Used as the negative class for `g4_fold`.

### 4. Complementary-strand i-motif candidates — `derived`

Reverse complements of annotated genomic G4 loci that themselves carry a canonical
four-C-tract architecture. These exist to give the joint G4/i-motif competition module real
complementary pairs. They are **motif calls, not folding evidence**, and are flagged as
such.

## Not bundled — download and ingest

These are the tables that turn QuadCond from a framework into a predictor. All are behind
publisher or repository downloads and are not redistributable here, so the repo ships the
adapters and not the data.

**Two of them are now in.** The G4STAB melting table (2,367 records, 2,274 usable Tm across
261 buffers) and the iM-Seeker pH_T set (160 measurements) have been downloaded and
ingested; `g4_tm` and `im_pht` are trained on them. See `docs/GET_THE_DATA.md` for the
exact commands and the traps in each file.

### G4STAB Supplementary Table 1 — experimental G4 Tm ✅ INGESTED

- **What**: 2,382 literature-derived data points: sequence, Tm, pH, and [K⁺], [Na⁺],
  [Li⁺/NH₄⁺]. This is the dataset the whole condition-aware Tm head is designed around.
- **Get it**: Oxford Academic article page → Supplementary data → `btaf545_supplementary_data.zip`
  <https://academic.oup.com/bioinformatics/article/41/10/btaf545/8266696>
- **Ingest**:
  ```bash
  quadcond atlas ingest g4stab-supp Table1.xlsx --dry-run
  quadcond atlas ingest g4stab-supp Table1.xlsx
  quadcond train --tasks g4_tm
  ```
- **Effect**: creates a real, measurement-grounded `g4_tm` head, and makes the condition
  ablation meaningful for Tm.

### iM-Seeker Supplementary Data Set — i-motif transitional pH ✅ INGESTED

- **What**: ~206 i-motif sequences with measured pH_T (120–171 retained as high confidence
  after thermal-difference-spectra QC), in 10 mM sodium cacodylate + 100 mM KCl over pH 4–8.
- **Get it**: NAR supplementary for doi:[10.1093/nar/gkae092](https://doi.org/10.1093/nar/gkae092),
  or the authors' figshare deposit linked from <https://github.com/YANGB1/iM-Seeker>
- **Ingest**: `quadcond atlas ingest imseeker TableS1.xlsx`
- **Effect**: creates the `im_pht` head — the first genuinely pH-aware i-motif output — and
  lets `im_architecture` be replaced by something grounded in measurements.

### 5DUVMA — condition-resolved i-motif stability *(new lead)*

- **What**: high-throughput UV melting of two model i-motifs, Tel21C ([C₃TAA]₃C₃) and C9
  ([C₉T₃]₃C₉), across pH 2.0–9.0 in 0.15-unit steps at ten ionic strengths
  (0.01–1.0 M KCl, Britton–Robinson buffer), 5–95 °C at 0.2 °C/min: 270 + 180 complete
  denaturation/renaturation curves, giving T½, pH½ and both transition widths.
- **Cite**: *High-throughput measurement and prediction of the i-motif DNA stability
  landscape.* Nucleic Acids Research 2026, 54(4):gkag110.
  doi:[10.1093/nar/gkag110](https://doi.org/10.1093/nar/gkag110)
- **Why it matters, and its limit**: this is *condition depth for two sequences*, not
  sequence breadth. It is the only public dataset that maps the pH × ionic-strength
  surface densely enough to fit a condition response, and it cannot on its own teach a
  model anything about sequence. Pair it with the iM-Seeker pH_T tables, which are the
  mirror image — 120–171 sequences at essentially one buffer. Neither alone supports a
  condition-aware i-motif model; together they do, and that pairing is the single most
  valuable thing to assemble next.
- **Ingest**: a declarative adapter fits this well once you have the supplementary tables:
  `quadcond atlas ingest-json adapters/5duvma.json TableSx.xlsx --dry-run`

### GSE220882 — iMab / BG4 CUT&Tag ✅ INGESTED

- **What**: genome-wide i-motif and G4 antibody occupancy in HEK293T and 93T449 (WDLPS),
  three biological replicates each. The in-cell positive set behind iM-Seeker's classifier.
- **Get it**: NCBI GEO, accession GSE220882 — 17 bigWigs, no peak calls, no alignments.
- **Ingest**: `scripts/06_gse220882_peaks.py` calls peaks and extracts sequence;
  `quadcond/atlas/ingest/gse220882.py` turns them into records. See
  [`GSE220882.md`](GSE220882.md) for why MACS2 is not an option and what replaced SEACR.
- **`label_class="genomic_proxy"` on every row.** These measure antibody occupancy in a
  nucleus, not folding in a buffer. `g4_fold` and `im_fold` are explicitly pinned to
  `biophysical` so this source cannot leak into them; it trains `im_fold_genomic` and
  `g4_fold_genomic`, which are reported separately and compared rather than combined.
- **8,482 i-motif and 6,706 G4 motifs** from reproducible HEK293T peaks, against
  composition-matched motifs drawn from dinucleotide shuffles of the same peak windows.

### Your own measurements *(the differentiator)*

Public tables are collapsed onto a handful of buffers. A lab that measures the **same**
oligo across a cation and pH grid supplies exactly the axis every published predictor
lacks. Expected columns (any subset, one row per measurement per condition):

```
sequence,name,kind,method,k,na,li_nh4,mg,ph,temperature,strand_conc,crowder_pct,
tm,ph_t,dg,folded,topology,replicate,notes
```

```bash
quadcond atlas ingest lab cd_melts_2026.xlsx --source deep_lab_cd_2026 --dry-run
quadcond atlas ingest lab cd_melts_2026.xlsx --source deep_lab_cd_2026
quadcond train
```

For a file whose columns need unit conversion or categorical remapping, write a small
JSON adapter instead — it records the conversion explicitly rather than leaving it in
someone's head:

```bash
cp data/templates/adapter_example.json adapters/my_source.json   # then edit
quadcond atlas ingest-json adapters/my_source.json melts.xlsx --dry-run
quadcond atlas ingest-json adapters/my_source.json melts.xlsx
```

## Other resources worth knowing about

| resource | why | where |
|---|---|---|
| Quadrupia | >140 M putative G4s across >108,000 genomes — cross-species generalisation | doi:10.1093/nar/gkae1073 |
| ONQUADRO | experimentally determined quadruplex structures, topology ground truth | doi:10.1093/nar/gkab1118 |
| G4RNA | experimentally tested RNA G4s — the RNA arm QuadCond does not yet cover | doi:10.1093/database/bav059 |
| G4-seq | in vitro G4 formation genome-wide under K⁺ and K⁺+PDS — two real conditions | GEO GSE63874 |
| BG4 ChIP-seq / CUT&Tag benchmarks | in-cell G4 positives across cell lines | <https://github.com/7YQXX3/G4-benchmark-datastes> |
| G4LDB 3.0 | G4/i-motif ligands, for a future ligand-aware condition axis | doi:10.1093/nar/gkab952 |

## Environment note

This atlas was assembled in a sandbox whose network egress was restricted to PyPI and
`raw.githubusercontent.com`. That is why the GitHub-hosted tables are bundled and the
publisher-hosted ones are not: it is a network restriction, not a licensing or scientific
judgement. On an unrestricted machine every source above is a direct download.
