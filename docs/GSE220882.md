# GSE220882: from bigWigs to trainable i-motif sequences

Zanin, I. *et al.* (2023) *Genome-wide mapping of i-Motifs reveals their association with
transcription regulation in live human cells.* NAR 51(16):8309–8321.
doi:[10.1093/nar/gkad626](https://doi.org/10.1093/nar/gkad626) · GEO
[GSE220882](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE220882)

This is the record of how the deposited signal tracks became atlas rows, including the two
places where the obvious plan does not survive contact with what was actually deposited.

## What is in the archive

`GSE220882_RAW.tar` unpacks to **17 bigWigs and three TPM tables**. Twelve of the bigWigs
are the CUT&Tag samples — HEK293T and WDLPS (93T449), iMab and BG4, three biological
replicates each — plus two H3K4me3 tracks and the RNA-seq tables.

There are **no BAMs and no BEDs**.

## Correction 1: MACS2 cannot run on this

`macs2 callpeak -f BAMPE` needs paired-end alignments. A bigWig is binned coverage; the
reads are gone. Running MACS2 on this series means going back to SRA and re-aligning,
which is a different and much larger job.

SEACR is the right caller anyway — it takes coverage, it is designed for the low-background
CUT&Tag regime, and it is what the authors used: Table S1 of their supplementary
information is headed "SEACR peaks for all samples tested".

## Correction 2: SEACR could not be run either, and what was done instead

SEACR is a bash wrapper around an R script and `bedtools`. The machine holding the data has
neither, and no network route to install them. So the peak caller here is a **Python
reimplementation of SEACR's no-control logic**, and every record it produces is flagged
`peak_caller=seacr_style_auc_blocks_reimplementation`. It does the part that does the work:

1. contiguous non-zero coverage blocks (bigWig runs that touch are one block);
2. each block's area under the curve and its maximum;
3. rank by AUC, take the top *n*.

The free parameter is *n*, and it did not have to be guessed. Table S1 gives the exact
peak count the authors obtained for each of the twelve samples, so the cut is made at their
number. The implied top-fraction then falls out as a check rather than an input — and it
lands between **0.94% and 1.04% on all twelve samples**, which is what a single
`SEACR ... 0.01 non` setting across the series would produce. The ranking reproduces
theirs closely enough that one threshold explains every sample.

| sample | blocks | authors' SEACR peaks | implied top fraction |
|---|---:|---:|---:|
| HEK293T BG4 r1–r3 | 4.6 M / 6.0 M / 6.8 M | 45,551 / 57,905 / 63,981 | 0.99% / 0.96% / 0.94% |
| HEK293T iMab r1–r3 | 4.2 M / 6.3 M / 5.3 M | 41,698 / 60,804 / 53,117 | 0.99% / 0.97% / 1.00% |
| WDLPS BG4 r1–r3 | 1.2 M / 1.4 M / 0.8 M | 12,458 / 14,153 / 8,138 | 1.02% / 1.01% / 1.03% |
| WDLPS iMab r1–r3 | 0.9 M / 0.5 M / 0.7 M | 9,031 / 5,469 / 7,263 | 1.03% / 1.02% / 1.04% |

## No lift-over

Every deposited bigWig is already hg38 (chr1 = 248,956,422). The lift-over step in the
original plan is unnecessary and was dropped.

## Reproducibility, blacklist, summit

- A region is kept only where **≥ 2 of 3 replicates** agree. The support depth is computed
  by a coordinate sweep in which each replicate contributes at most 1, so two overlapping
  blocks *within* one replicate cannot stand in for two replicates.
- Regions overlapping the **ENCODE hg38 blacklist v2** are dropped (`data/genomic/`).
- The summit is the highest-signal position of the best-supported replicate block, clamped
  into the reproducible region — the ≥2-replicate intersection is narrower than the block
  it came from, so 31% of raw summits fell outside it.

| | ≥2/3 replicates | after blacklist |
|---|---:|---:|
| HEK293T BG4 stringent | 31,992 | 29,225 |
| HEK293T iMab stringent | 24,847 | 22,730 |
| WDLPS BG4 stringent | 3,622 | 3,209 |
| WDLPS iMab stringent | 891 | 767 |

A `relaxed` tier at twice the authors' peak count is emitted alongside.

## Sequence, without a genome download

UCSC and Ensembl are both unreachable from this environment. The sequence instead comes
out of a **STAR index**, which stores the reference in `Genome` as one byte per base with
per-chromosome offsets in `chrStart.txt` — a perfectly good random-access FASTA substitute.

The decoding is verified before a single sequence is written, against the index's own
annotated splice junctions: real introns begin GT and end AG (CT/AC read on the minus
strand). A correct decode scores ~96%; random bytes would score ~0.4%. The observed
2,000-junction check gives **96.1% canonical**, and the residue is GC-AG, CT-GC and AT-AC —
the genuine minor-spliceosome classes, not noise. If the check fails the script exits
rather than writing sequences that might be wrong.

## The finding that shaped the ingestion

Peak windows are 201 nt centred on the summit. Asking how often they contain a canonical
four-C-tract i-motif, against 40,000 random N-free hg38 windows of the same length:

| | n | canonical motif | vs random genome | vs dinucleotide shuffle of itself |
|---|---:|---:|---:|---:|
| HEK293T iMab | 22,727 | 37.3% | **9.6×** (3.9%) | 1.36× |
| HEK293T BG4 | 29,223 | 22.9% | **10.9×** (2.1%) | 1.75× |
| WDLPS iMab | 767 | 9.5% | 2.4× | 1.38× |
| WDLPS BG4 | 3,209 | 3.6% | 1.7× | 1.36× |

Two things follow, and both change what gets ingested.

**Most of the enrichment is composition.** Nearly tenfold over random genome collapses to
1.4× against a dinucleotide shuffle of the same windows. A classifier trained on
peak-versus-random-genome would learn GC content and report a triumphant AUROC for it. So
the negatives are built by shuffling each peak window and taking the best canonical motif
*from the shuffle* — positives and negatives then match on composition and both carry a
four-tract motif, and only the architecture separates them.

**The ingested sequence is the motif, not the window.** A 201 nt window is not comparable
to a 25 nt designed oligo, and training on windows trades one domain shift for another.
The record is the best canonical motif inside the window, searched on both strands (CUT&Tag
maps a duplex locus; the C-rich strand may be either one), with the window kept as
`genomic` context. Windows with no canonical motif are counted and reported rather than
ingested — 63% of the strongest i-motif peaks contain none, and that number is a result,
not a nuisance.

**WDLPS is ingested but not trained on.** Those libraries are roughly a tenth the depth and
their peaks sit barely above genomic background. The rows exist under their own source
names; `cell_lines=("HEK293T",)` is the default.

## Provenance

Every row: `evidence_tier="experimental"` (something was measured) and
`label_class="genomic_proxy"` (what was measured is antibody occupancy at a locus, not
folding in a defined buffer). The attached condition is nominal intracellular chemistry
with **every field marked imputed**, so no condition-response head can mistake it for a
datum. `g4_fold` and `im_fold` are pinned to `label_class="biophysical"` so that adding
this source cannot silently change what their probabilities mean; the peak-derived rows
train `im_fold_genomic` and `g4_fold_genomic` instead.

## Running it

```bash
# wherever the bigWigs are; needs only numpy + pyBigWig
python scripts/06_gse220882_peaks.py \
    --bigwig-dir GSE220882_RAW \
    --genome-star /path/to/STAR_index \
    --blacklist data/genomic/hg38-blacklist.v2.bed \
    --out data/external/downloads/gse220882_peaks.jsonl

python scripts/01_build_atlas.py       # picks the file up automatically
python scripts/02_train.py
python scripts/07_validate_external.py # the check this was all for
```

Roughly 30 seconds for all twelve samples.
